# 技術的な注意点・不変条件・既知の制限・未実装・未検証

README.md から移動した注意事項。

## 既知の制限

- 応答の deletehash は画像ごとに localStorage に残り、拡大表示の「imgur から削除」で消せる。匿名アップロードは imgur 側に管理画面がないので、この端末以外からは消せない。
- 同じ画像を再度アップロードしても重複チェックはしない。
- iOS はタブのままだと7日触らないとサイトデータを消すことがある。ホーム画面に追加して使うと残りやすい。

## Service Worker(sw.js)

- ナビゲーションは固定キー `'index.html'` で読み書きする(hateb-tycoon の `docs/decisions/sw-navigate-fixed-key.md` と同じ理由)。認可の戻り(`?code=` / `?error=`)はキャッシュしない。`build-info.js?nc=…`(起動時の更新確認)は素通し。
- 更新確認(`checkUpdate`)の `?v=<sha>` への移動は SW 導入後もそのまま動く(ナビゲーションは常にネットワーク優先)。
- Claude Code 等のサンドボックス化されたブラウザでは `navigator.serviceWorker.register()` が失敗して SW を確認できない。SW のロジックは Node で模擬の `caches`/`fetch` を作って確かめ、実機は本番オリジンで `caches.keys()` を見る。

## 未検証

- **「Gifアニメのみ」の実機確認**: 本体で `backfill_animated.py` を流し、`export_static.py --go` で一覧を作り直してから、アニメ絞り込みで動く gif だけが出ること、Gifのみとの件数差、再読み込み後も選択が残ることを見る(一覧が古いうちは何も出ない)。確認できたら CHANGELOG に「確認済み」と1行残して、この項目を消す。
- オフライン対応(sw.js・一覧の控え)は、模擬の Dropbox でのアプリ側(通信不能で起動→一覧表示→検索、オンライン復帰で読み直し)と、Node での SW のロジックだけ確認した。実機の iOS(ホーム画面の PWA)で、機内モードの完全終了→再起動後に、一覧が「· オフライン」付きで出ること・検索が効くこと・キャッシュ済みのサムネイルと原寸が出ること・オンライン復帰で自動で読み直すことは未確認(ページが開くことと、メモの追加は確認済み)。

- 起動時の一覧の並列読み込み・端末キャッシュ(`gt-index-v1`)・サムネ3本並列は、模擬の Dropbox(遅延つき)でだけ確認した。実機の iOS Safari での体感と、Dropbox の 429 が増えないか(月別6本・サムネ3本の並列)は未確認。
- 年月ラベルのドラッグ(タッチ)は、模擬データ(8,580枚)でイベントを手で送って確認しただけ。実機の iOS Safari でのつかみやすさ・システムのスクロール表示との重なり・数千枚描画後の動作は未確認。
- 検索フォームのフッター(`#sbar`)は、iOS でキーボードを出したときに `visualViewport` の分だけ持ち上げる実装。実機では確認していない(PC のブラウザで幅 320〜375px の見た目だけ確認)。
- 拡大表示のメモ欄(`#lbt`)は、実機の iOS Safari でキーボードを出したときの見え方(下に固定した説明欄がキーボードに隠れないか)と、キーボードを閉じたときに保存されるか(focusout)を確認していない。
